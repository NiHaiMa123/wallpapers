## 1. 全面检查 experimental 文件移动后的路径回归

上一轮只做了 Python 语法检查，但这不足以证明移动后仍可运行。

重点扫描：

```text
scripts/experimental/**
workflows/experimental/**
```

检查所有与文件位置有关的逻辑，包括但不限于：

```text
__file__
Path(__file__)
parents[n]
.parent
dirname(...)
PSScriptRoot
Split-Path
../
../../

scripts/
workflows/
presets/
prompts/
history/
artifacts/
outputs/
reports/
inputs/
config/
```

目标：

> experimental 文件移动前如果可以按其历史用法执行，移动后不能因为 repo-root 推导、相对路径或 import 位置变化而直接失效。

### 已确认的三个问题必须修复

#### A. `scripts/experimental/build_seamless_wallpaper.py`

当前代码类似：

```python
sys.path.insert(0, str(Path(__file__).resolve().parent))
from loop_common import playback_indices
```

移动后会在 `scripts/experimental/` 找 `loop_common.py`，但实际文件在：

```text
scripts/loop_common.py
```

请修为对当前目录结构稳定的 repo/script-root 推导方式。

不要通过要求用户手工设置 `PYTHONPATH` 来掩盖代码路径问题。

同时更新 `scripts/experimental/README.md` 中错误或过时的依赖说明。

---

#### B. `scripts/experimental/run_h3_generate.py`

它原来位于 `scripts/`，移动到 `scripts/experimental/` 后，旧的：

```python
dirname(dirname(__file__))
```

或等价逻辑已经不能得到仓库根。

当前会错误解析：

```text
scripts/workflows/
scripts/presets/
```

而真正路径在仓库根：

```text
workflows/
presets/
```

请修正 repo root 推导。

同时检查它的默认 prompt。

原默认类似：

```text
prompts/MINIMAX_H3_LIVE2D_CRYSTAL_LOCK_LOOP_PROMPT_V7_BODY_ONLY.md
```

该文件目前已经进入：

```text
history/prompts/
```

因为此脚本本身已经是 experimental/history-era 工具，可以：

* 显式指向历史 prompt 的新路径；或
* 去掉这个易失效的默认，要求显式传入；
* 选择哪种方式以最小改动和历史可复现性为准。

不要把历史 V7 prompt 重新搬回生产 `prompts/`。

---

#### C. `scripts/experimental/run_h3_window_probe.py`

当前类似：

```python
PROJECT_ROOT = Path(__file__).resolve().parents[1]
```

移动前这可能是仓库根，移动后已经变成：

```text
repo/scripts
```

结果例如：

```text
PROJECT_ROOT / "artifacts"
```

会变成：

```text
scripts/artifacts/
```

请修为真正仓库根。

同时检查其中所有：

```text
artifact_dir
output path
workflow/report path
```

是否受移动影响。

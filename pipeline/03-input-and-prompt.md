# 03 输入图检查与提示词

## 先看图，再写动作

对输入图记录：

- 人物身份、脸、瞳色、发型、服装、身体比例；
- 手、脚、剑、武器、饰品和其他高风险结构；
- 可以自然运动的软质区域；
- 必须静止的硬质前景和背景；
- 已经存在的花瓣、粒子、反射、灯光或烟雾；
- 花瓣、烟雾、粒子、反射或光效是否包含无法在片内自然回到起点的单向事件。

## I2V 提示词结构

提示词按以下顺序写：

1. 一个连续镜头、固定机位、画面材质和主体。
2. 输入图必须保留的身份、姿态、构图和结构。
3. 最多 2–3 个相容的运动系统，每个写清来源、连接区域、幅度和时间。
4. 开始—中段—结束的时间弧。
5. 镜头、身份、解剖、背景和材质的排除项。

不要用 `dynamic motion`、`cinematic camera`、`dramatic movement` 等无边界词。

## LoRA 与 token

- `LoraStrength > 0`：提示词以 `hmmotion` 开头。
- `LoraStrength = 0`：不要写 `hmmotion`。
- 用户没有成人 LoRA 意图时，默认强度 0；不要因为仓库存在 HMNSFW 模型就自动启用。

## 原生首尾循环时间弧

标准 `draft`、`long_draft` 和 `final` 都使用 `-LoopLock`，在一个片段内部完成完整周期。LoopLock 用同一张源图锚定首帧和末帧，两端外观本来就会有残差；如果末端停死，循环时会先刹住再轻轻跳回首帧。

```text
0–10%：源图姿态，以很小的周期余速离开，不要从完全静止起步
10–40%：低幅离开源状态
40–60%：到达周期极值并开始自然回程
60–85%：沿物理一致的轨迹回到源状态
85–100%：提前回到源姿态附近，保持与片头同量级的余速穿过边界；禁止末段停死
```

首尾必须同时收敛：姿态、视线、发丝和布料附着位置、道具、背景、反射与光照。首尾外观相近仍不代表速度连续；片头片尾的运动导数要匹配，不要把两端都压到 0。

动作必须能在片内自行闭合：呼吸完成完整周期，发丝和布料摆动后回位，光效完成明暗周期。落花、烟雾和飞行粒子不得持续单向穿越画面；将它们冻结、限制为原位明暗变化，或设计成很小的闭合轨迹。行走、说话、喷溅、道具开关等无法平滑回到首帧的事件不进入默认壁纸提示词。

## 稳定性约束

按画面需要锁定：脸、瞳色、发型根部、手指、身体比例、服装拓扑、道具连接、固定焦距、背景布局、文本和灯具。

动作幅度必须符合壁纸需求。模型多次忽略更严格文字时，不再无限堆提示词；保持提示词，切换 seed 继续筛选。

不要承诺输出能逐像素保持输入图；应明确希望保持的结构，并由实际解码结果和验收决定是否通过。

## 文件落盘

执行请求把英文可执行 prompt 保存为：

```text
prompts/generated/<subject>_<route>_<motion>_vN_en.txt
```

要求：UTF-8、纯文本、文件名安全、版本不覆盖，不使用在线接口的六段式参考模板。可以在文件外另附中文解释。记录文件 SHA-256。

## 产物

- 输入图视觉清单；
- motion contract；
- prompt 文件及 SHA-256；
- 与 prompt 一致的 LoRA 和循环策略。

## 晋级条件

提示词只控制动作、保存、镜头和排除项，不重新发明输入图的外观；运动系统不超过三个且循环语义自洽。

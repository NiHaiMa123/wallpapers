# 04 Native 1080p / 73f Take Contract

## Purpose

定义 Gate B 选定 video seed 后的正式高成本候选生成。该阶段输出真正供用户 Gate C 选择的 1080p take，并保留后续逐帧人工筛选所需的无损帧证据。

## Target output

```yaml
visible_resolution: 1920x1080
frames: 73
fps: 24
silent: true
camera: locked
loop_mode: same_image_first_last_anchor
```

以上是当前生产 Contract。改变正式分辨率、帧数、默认 fps 或默认 loop semantic 属于 Contract Change，不得由 subagent 因实现方便自行调整。

`same_image_first_last_anchor` 表示：同一张用户选定静态图同时约束生成序列的首端和末端，使 H3 生成本身具有返回起点的意图。当前实现可以把它叫 `LoopLock`、`last_frame` anchor 或其他名字，但 Contract 定义的是语义，不绑定脚本参数名。

## H3 internal geometry

当前已知 H3/ComfyUI 执行约束允许使用：

```text
internal generation/decode: 1920x1088
visible/delivery frame:      1920x1080
```

`1920×1088` 是内部实现空间，不应被报告成最终成片分辨率。实现必须明确记录从内部尺寸到可见 1920×1080 的转换方法，并避免未记录裁切。

如果未来模型/节点可以直接稳定生成 1920×1080，主 Agent可在证据充分后更新本 Contract。

## Inputs

```yaml
selected_image:
selected_image_sha256:
motion_prompt_file:
motion_prompt_sha256:
selected_video_seed:
lora_policy:
loop_intent: same_image_first_last_anchor
```

## Required invariants

- 必须使用用户 Gate B 选定的 seed；
- 必须使用 Gate A 选定的静态图；
- motion prompt/LoRA/主要动作约束在同一组正式 take 内保持一致；
- 同一 selected image 必须作为 first-frame 与 last-frame anchor 的语义来源；
- 不能因为 streaming/逐帧输出方便而丢掉 last-frame anchor；
- 输出必须静音；
- 正式执行前满足 `01-runtime.md`；
- 每个 take 使用唯一 RunId；
- 必须保留完整帧证据，优先直接保存 1920×1080 PNG 序列，而不是只保留有损 MP4 后再拆帧。

首尾同图锚定只保证“返回起点意图”，**不保证边界速度自然**。H3 常见末端减速/冻结由 Gate D 人工帧选择处理，不因此取消 anchor 语义。

## Multiple takes

相同 seed 允许生成多个高分辨率 take，因为跨会话、版本或运行状态可能产生不同结果。每个 take 都是独立候选，必须分别记录 hash 和视觉结论。

## Forbidden behavior

- 因低画质 seed 通过而自动 Gate C；
- 把低分辨率输出放大冒充本阶段输出；
- 生成错误依赖 RIFE/超分修复；
- 丢弃原始帧序列，只留下最终压缩视频；
- 为了逐帧输出或省实现工作量，退化成只有 first frame 的普通 I2V；
- 使用 `probe`、`smoke`、实验 profile 名称冒充生产语义而不在 Contract Review 中说明。

## Outputs

每个正式 take 至少产出：

```yaml
run_id:
selected_seed:
input_image_sha256:
motion_prompt_sha256:
internal_resolution: 1920x1088
visible_resolution: 1920x1080
frames: 73
fps: 24
silent: true
loop_mode: same_image_first_last_anchor
first_anchor_image_sha256:
last_anchor_image_sha256:
frame_sequence_dir:
frame_sequence_manifest:
preview_video:
run_report:
take_sha256:
visual_findings:
```

`first_anchor_image_sha256` 与 `last_anchor_image_sha256` 必须等于 selected image SHA-256。

## Gate C

Agent 可以淘汰明显结构错误并给推荐，但最终 take 由用户选择。

```yaml
status: WAITING_FOR_USER_SELECTION
```

用户选择后记录：

```yaml
selected_take:
selected_take_sha256:
selected_frame_sequence_dir:
selection_notes:
status: SELECTED
```

## Acceptance

本阶段完成不代表尾部速度已完美。只要求：

1. 正式 1080p/73f/24fps/silent 规格满足；
2. 首尾同图 anchor 语义真实存在；
3. canonical PNG 帧证据完整；
4. 用户选出一个主体质量足够高、值得进入 Gate D 的正式 take。

# 02 T2I Contract

## Purpose

把已批准/当前有效的 Director Brief 转成静态候选图，为后续 H3 I2V 提供稳定首帧。

## Inputs

```yaml
director_brief:
t2i_prompt:
seed_policy:
target_aspect_ratio: 16:9
candidate_count:
```

T2I prompt 必须从 Director Brief 派生，不允许跳过导演规划直接把用户一句话机械扩写成最终生成指令。

## Required invariants

候选图必须同时满足两类目标：

1. 单帧审美：主体、姿势、构图、光线、场景和视觉焦点成立；
2. I2V 可执行性：脸/手/肢体/道具结构清晰，软质可动区域有清楚轮廓和运动空间，硬质区域可被稳定锁定。

T2I 阶段必须记录执行 prompt、seed 和候选来源。不得只保留“最终那张图”而丢失其生成参数。

## Allowed implementation freedom

- 可以使用 H3 pseudo-T2I 或仓库后续验证的其他静态图执行器；
- 分辨率可由具体 T2I 能力决定，只要输出适合作为 16:9 I2V 首帧；
- 可以由 Agent 做明显结构错误的初筛。

如果更换 T2I 引擎会改变项目能力边界，应由主 Agent更新本 Contract 或新增引擎子 Contract。

## Forbidden behavior

- 自动替用户完成 Gate A 最终审美选择；
- 生成后偷偷裁切/改图导致记录的输入和实际 I2V 首帧不一致；
- 未授权启用可选成人动作 LoRA；
- 把一张结构明显错误的静态图交给 I2V 希望后续自动修复。

## Outputs

```yaml
director_brief_file:
t2i_prompt_file:
t2i_prompt_sha256:
candidates:
  - path:
    sha256:
    seed:
    technical_findings:
agent_recommendation:
status: WAITING_FOR_USER_SELECTION
```

## Acceptance

Gate A 之前：至少有可供用户比较的候选及其可追溯参数。

Gate A 之后：记录唯一 `selected_image` 与 SHA-256，后续所有 seed screen 必须明确引用该图；更换图片即视为新的上游版本。
